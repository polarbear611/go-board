## 1. M1 测试 —— 初始局面分离 + 保存/加载（localStorage）

### 1.1 单元测试：`src/utils/goRules.test.js`（V0.1 逻辑基线）
坐标约定：`[row][col]`，0-indexed，19×19。每条用例由测试 agent 编码精确坐标并实跑验证。

| # | 场景 | 期望 |
|---|---|---|
| U1 | 角上单子被提：白封住黑 (0,0) 的两口气，最后一手落子 | `valid:true`，`captured===1`，该点变 null |
| U2 | 整块被提：白包围黑两子连通块，最后一手 | `valid:true`，`captured===2`，两点变 null |
| U3 | 禁着点（自杀）：落子后己方块无气且不提子 | `valid:false`，`reason:'suicide'` |
| U4 | 提子后有气则合法：落子同时提掉对方、己方获得气 | `valid:true`，`captured>=1` |
| U5 | 占用点：落在已有子的点 | `valid:false`，`reason:'occupied'` |
| U6 | 单劫禁手：黑提一子成劫，白立即原点回提 | `valid:false`，`reason:'ko'` |
| U7 | 隔一手后可回提：劫材后劫不再禁 | `valid:true` |
| U8 | `boardEquals`：同形/异形判定 | 正确返回 true/false |

### 1.2 单元测试：`src/api/problems.js`（localStorage 版）
| # | 场景 | 期望 |
|---|---|---|
| A1 | `saveProblem` 后 `getProblem` 往返一致 | 黑/白子数组、先手方完全相同 |

## 4. M4 测试 —— 标记死子 + 中国规则数子

### 4.1 单元测试：数子算法
构造 3~4 个**已知答案**的小终局棋形，断言数子结果与手算一致：

| # | 棋形 | 期望 |
|---|---|---|
| C1 | 纯空盘对半分割（一道墙） | 双方地各半，单官不计 |
| C2 | 一方完整围空 + 对方活棋 | 各自 = 活子 + 独占空点 |
| C3 | 含死子：标记死子后 | 死子归还对方地，归属翻转，比分随之变化 |
| C4 | 贴目判定：黑地 - 贴目 vs 白地 | 胜负方正确 |

数子规则断言（中国规则）：
- 每方得分 = 己方棋盘活子数 + **仅被己方包围**的空点数。
- 双方均可到达的空点（单官）不计入任何一方。
- 总点数自洽：黑 + 白 + 单官 = 361 − 死子已移除部分。

### 4.2 手动验收清单
- [ ] 双 pass 进入「标记死子」→ 点击某块标灰、再点取消，切换正常。
- [ ] 终局面板显示「黑 X 子 / 白 Y 子 / 黑胜（负）N 子」。
- [ ] C1–C4 棋形实操结果与文档期望一致。
- [ ] `npm test` 全绿；`npm run build` 通过；线上冒烟通过。
