# 音效素材

| 文件 | 事件 | 时长 |
|---|---|---|
| `stone.mp3` | 落子 | 120ms |
| `capture1.mp3` | 落子 + 提 1 子 | 621ms |
| `capture-many.mp3` | 落子 + 提多子 | 1079ms |

由大模型生成（黄钦提供原始 wav），无第三方版权。

**每个文件是完整的一次事件，提子那两个已经把落子声混在里面了** ——
所以播放时一个事件只放一个文件，不要再叠一次 `stone.mp3`。
`capture1` 是「落子 → 停 446ms → 提子×3」，`capture-many` 是「落子 → 停 → 提子×10」。

## 处理过程（原始 wav → 这里的 mp3）

1. **切掉 73–76ms 前导静音**。原始文件每个都有，那是点击到出声的真实延迟，
   超过 50ms 就能感觉到发闷。只保留 4ms 前导，避免削掉起音。
2. **统一响度**：三个文件的首击（都是落子）峰值归一到 0.85。
   原始 `sound_go` 是 0.893、另两个 0.705，直接用会觉得提子时落子声突然变小。
3. 尾部留 50ms，首尾各加 2ms/5ms 淡变防咔哒。
4. 编码 mp3 192k 单声道：实测浏览器解码后起音与 wav 完全一致（5–7ms），
   无编码器延迟，体积 161KB → 48KB。
